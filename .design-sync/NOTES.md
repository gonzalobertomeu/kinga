# design-sync notes — @kinga/ui

## Repo gotchas

- `[GENERAL]` `packages/ui/package.json` had no `types`/`main`/`module` field (only `exports["."] -> src/index.ts`, since internal apps consume source directly via a tsconfig path alias, not package.json resolution). The converter's `.d.ts` entry lookup (`lib/dts.mjs#projectFor`) reads `pkgJson.types`/`typings` directly and ignores `exports`, so with neither set it looked for `<pkgDir>/index.d.ts` (doesn't exist) and silently found 0 exported PascalCase symbols. Fix: added `"main": "./dist/index.js"`, `"module": "./dist/index.js"`, `"types": "./dist/index.d.ts"` to `packages/ui/package.json`. These are additive — they don't affect internal builds since `exports` still wins for anything that supports conditional exports.
- `[GENERAL]` The Vite library build's compiled `dist/index.css` (339 bytes — this DS today has exactly one small Button) was mis-detected as a stub by the `<500B` heuristic in `lib/css-fallback.mjs` (`[CSS_PLACEHOLDER]`), even though it's real compiled CSS. Fixed by explicitly setting `cfg.cssEntry: "dist/index.css"` (resolved relative to the package dir, i.e. `packages/ui/`) in `.design-sync/config.json`. Revisit if this ever produces stale/duplicate CSS once the DS has more components and the real bundle grows past 500B (the heuristic would stop misfiring, but the explicit `cssEntry` should still be harmless).
- `[GENERAL]` `cfg.storybookConfigDir` must point at the `.storybook/` directory itself (`packages/ui/.storybook`), NOT the package directory (`packages/ui`). Setting it to the package dir silently broke `lib/source-storybook.mjs#resolveStorySources`'s base-path resolution for story `importPaths` (index.json's importPaths are relative to the storybook project root = the `.storybook`'s parent) — every component fell back to a synthesized/floor preview instead of a real compiled story ("story sources: 0/0 stories paired" in the build log). No visible error — just silently wrong previews. Fixed and confirmed via "story sources: 2/2 stories paired to module exports".
- Package is a Bun workspace member (`packages/ui`) inside the `kinga` monorepo. `--node-modules packages/ui/node_modules` works fine (Bun links `react`/`react-dom` per-package, not only hoisted at the repo root) — no need for the repo-root node_modules fallback.
- `packages/ui` has no pre-existing "build" script for consumers (internal apps import `src/index.ts` directly via Vite/bun). Added a dedicated `vite build` library-mode build (`vite.config.ts`, `vite-plugin-dts`) purely so a real `dist/` exists for this sync — internal consumption is unaffected.
- TypeScript 7 (native compiler) doesn't expose the classic JS Compiler API that `vite-plugin-dts`/`unplugin-dts` need. Had to add `@typescript/typescript6` as a devDependency in `packages/ui` for the dts generation to work. Unrelated to design-sync itself, but anyone reproducing this build from scratch will hit the same error.

## Re-sync risks

- 6 components as of 2026-09-22 (Badge, Button, Card, Checkbox, Input, Select), 16 stories, all graded `match` story-by-story after the Braun/TE restyle. Single `components` group → `components/components/<Name>/`.
- `titleMap: {"Colors": null}` excludes `Foundations/Colors` (a token palette page, not a component). New foundation pages need the same treatment or they'll surface as `[TITLE_UNMAPPED]`/bogus components.
- The `.storybook/preview.tsx` decorator is bundled as the preview wrapper. It themes `document.body` via `data-kinga-theme` — NOT a sized wrapper. A wrapper with `minHeight: 100vh` made every card cell 848px tall with a tiny component; theming `<html>` instead left the preview card's own white `<body>` on top. Keep it on `body`.
- No `cfg.provider`: components need no wrapper (light tokens are on `:root`), so the decorator is harness-only (canvas bg + padding). README wrap guidance lives in `conventions.md`.
- `cfg.overrides.Input.cardMode: "column"` (Input is `width: 100%`). Select is now fit-content, so it no longer risks `[GRID_OVERFLOW]`.
- Fonts: system stacks only; nothing ships. `[FONT_MISSING]` fires for any named family in `--kinga-font-*` that isn't a system font — "JetBrains Mono" was removed from the mono stack for that reason. If a real webfont is adopted, ship it via `cfg.extraFonts`.
- Select's styled dropdown (`appearance: base-select`) only exists in Chromium 135+; previews/graders only see the closed field, so the open-tray styling is NOT verified by the compare harness — check it manually in Storybook after touching `Select.module.css`.
- `docs: 0/6 components matched` — no JSDoc on components except Button's `variant` prop.
- Rebuild BOTH `dist/` (`buildCmd`) and `.design-sync/sb-reference` after any DS source change; a stale reference trips the reference-drift canary.
